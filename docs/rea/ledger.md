Conventions

* **Status**: `observed` (the artifact says so) / `inferred` (analyst reading of observed facts) / `unknown`.
  Mixed rows say which part is which.
* **Authority**: `shipped-artifact` (the 26.3.0 app bundle, by REA tool output or shell inspection),
  `historical-reference` (the 26.3.0 LGPL source tarball, read for behaviour, cited `file:line`; it is the
  published source, not the shipped binary), `analyst-inference`.
* **Evidence**: `REA ev_xxxxxxxx…` = REA Evidence ID (full IDs in `README.md` and the `wine-fork.md` evidence
  index; JSON under `evidence/`); `SH-TT-nn` = plain-shell observation from the text-tooling pass. **SH-TT IDs
  resolve to the four report tables** (`env-table.md`, `renderer-selection.md`, `bottle-format.md`,
  `app-tweaks.md`), not to `evidence/text-tooling-observations.json`: that file indexes only 49 of the records
  (missing SH-TT-21, 28, 31, 32, 52 → `env-table.md`; 59, 63 → `renderer-selection.md`; 67 → `bottle-format.md`;
  78, 79, 81, 82, 83 → `app-tweaks.md`) and three of its locations are stale (SH-TT-71 `16277`, SH-TT-72 `269`,
  SH-TT-77 `16219-16289`; the corrected values are in the reports and in L-34/L-66/L-69 below; the JSON is raw
  output and left untouched). `shell:` = plain shell on the unzipped bundle (`evidence/shell-*.txt`); `src:` =
  `sources/wine/` of the LGPL tarball. Ghidra addresses are file offsets in the named binary. Only REA output
  carries an Evidence ID; everything else is labelled as the shell/text observation it is. REA `inspect_macho`
  records hold load commands, imports, exports and rpaths only — never a string inventory — so every string fact
  below is cited to a `shell-*-strings.txt` file:line, not to an `inspect_macho` ID.
