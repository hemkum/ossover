### GStreamer and Rosetta handling in the launcher (asked explicitly)

* GStreamer: the only logic is SH-TT-20/21 below — if `$CX/lib64/gstreamer-1.0` exists, export `GST_PLUGIN_SYSTEM_PATH` to it and point `GST_REGISTRY` at a per-user registry file. The directory ships 17 plugin dylibs (`libgstapplemedia`, `asf`, `audioconvert`, `audioparsers`, `audioresample`, `avi`, `coreelements`, `deinterlace`, `id3demux`, `isomp4`, `opengl`, `playback`, `typefindfunctions`, `videoconvertscale`, `videofilter`, `videoparsersbad`, `wavparse`) plus `include/` (observed `ls`). Nothing else (no `GST_DEBUG`, no plugin path for the bottle).
* Rosetta: the launcher never checks whether Rosetta is installed; it only sets `ROSETTA_ADVERTISE_AVX=1` unless the user pre-set it (a pre-set `0` or empty value causes the variable to be **deleted**, because "Rosetta doesn't take any value to mean disable", `wine:724-738`). The Rosetta install prompt lives in the GUI (observed `Base.lproj/RosettaInstallation.nib` name and `Localizable.strings` entries "To use %1$@, you need to install Rosetta…", "Rosetta installation failed…"). Historical-reference: `src/dlls/ntdll/unix/signal_x86_64.c:2024-2026` comments that XGETBV emulation claims AVX/AVX-512 on Sequoia+ "arguably only if ROSETTA_ADVERTISE_AVX is set" but does so unconditionally.
